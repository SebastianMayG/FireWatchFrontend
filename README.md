# FireWatch — Frontend

<p align="center"><img src="src/assets/logo.png" alt="FireWatch" width="160"></p>

Interactive web app to explore the historical activity of fire hotspots in **Mexico** (~2000 to today) using harmonized **MODIS** and **VIIRS** data from NASA FIRMS. Built for the NASA Space Apps Challenge.

**Live demo: https://www.firewatch.study/**

This repo is the frontend only. All data is processed and harmonized by the [FireWatchBackend](https://github.com/SebastianMayG/FireWatchBackend) (FastAPI); see its [API contract](https://github.com/SebastianMayG/FireWatchBackend/blob/main/docs/api.md) and [harmonization methodology](https://github.com/SebastianMayG/FireWatchBackend/blob/main/docs/metodologia_armonizacion.md).

## Features

- **Interactive map of Mexico** with zoom, pan and desktop-style rectangular area selection (click and drag).
- **Hotspot layer** for the selected year and **recurrent wildfire zones** painted directly on the map, with tooltips.
- **Indicators**: detected hotspots, most active year, most active months, change vs. historical median, years analyzed.
- **Historical calendar** (months × years heatmap) with the selected year highlighted, and **annual trend** chart.
- **Compare** view: the same area in two different years, side by side, on a consistent color scale.
- **Exports**: CSV (generated by the backend) and an interpretive PDF report (generated in the browser, including the map as shown).
- English / Spanish and light / dark mode.

## Requirements

- Node `^22.18.0` or `>=24.12.0`
- The backend running (default: http://127.0.0.1:8000)

## Configuration

The backend URL is read from `VITE_API_URL`. If your backend runs elsewhere, copy `.env.example` to `.env` and adjust it:

```
VITE_API_URL=http://127.0.0.1:8000
```

The backend must allow the frontend origin in CORS (`CORS_ORIGINS`; by default it accepts http://localhost:5173).

## Deployment

The app is deployed as a static site on **Azure Static Web Apps**.

1. Set `VITE_API_URL` to the production backend URL (in `.env.production` or as a build environment variable). Vite inlines it at build time, so changing it requires a rebuild.
2. Run `npm run build` and publish the `dist/` folder.
3. `public/staticwebapp.config.json` rewrites unknown routes to `index.html` so client-side routes (`/compare`, `/about`) work on reload.
4. Add the production frontend origin to the backend's `CORS_ORIGINS`.

## Project structure

```
src/
  api/          HTTP client and API types
  stores/       Pinia state: year, selected area, backend data
  router/       routes (Dashboard, Compare, About)
  views/        DashboardView, CompareView, AboutView
  components/
    layout/     header (language, dark mode, About link)
    map/        map (hotspots, recurrent zones, area selection) and map controls
    indicators/ indicator cards
    charts/     calendar heatmap and annual trend (ECharts)
  composables/  useReport (PDF report), useTheme (dark mode)
  pdf/          PDF report builder and analysis interpretation text
  theme/        PrimeVue preset with the design tokens
  i18n/         EN/ES translations
```
